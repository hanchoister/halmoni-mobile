# Supabase schema for halmoni-mobile

**`schema.sql` is the source of truth.** It is the recorded shape of the live
production database (`halmoni-prod`, `wyovvbnlhyqfmnvsgket`), and it moved here
from the `tend` repo on 2026-09-01 when Halmoni became mobile-only.

Do not treat `migrations/` as authoritative — see below.

## Layout

| Path | What it is |
| ---- | ---------- |
| `schema.sql` | The canonical schema. Recorded from prod, not generated by a migration run. |
| `applied/` | Every patch applied to prod, newest last. Each is idempotent and ends with a self-verifying `select`. |
| `migrations/` | **Historical. Not the source of truth.** See the warning below. |
| `config.toml` | Supabase CLI config. |

## Why `migrations/` is not authoritative

`00`–`05` were written before the mobile app pointed at production, and they
describe tables that prod already had with *different* columns. Running them
against prod would not reproduce it, and their `IF NOT EXISTS` guards mean they
would silently no-op rather than fail loudly. `06_invites.sql` is a recording of
objects created by hand in the dashboard and is documentation only — **do not
apply it**.

They are kept because they are the only written record of the original intent.
Treat them as history.

## Making a change

1. Write a patch in `applied/`, named `patch_<what_it_does>.sql`.
2. Make it idempotent, and end it with a `select` whose rows should all read
   `true`, so applying it proves itself.
3. Dry-run it inside `begin; ... rollback;` first — several patches in this
   folder were corrected because the dry run failed.
4. Apply it in the SQL editor against **halmoni-prod** (check the project name).
5. Update `schema.sql` to match.
6. Run `./scripts/check-drift.sh` from the repo root. It must be silent.

## Schema conventions

- Every user-owned row has `family_id UUID NOT NULL REFERENCES families(id)`.
- `updated_at TIMESTAMPTZ NOT NULL DEFAULT now()` — trigger bumps on UPDATE.
- `deleted_at TIMESTAMPTZ` — soft-delete tombstone. Sync clients treat non-null
  as a delete signal but keep the row for tombstone-aware merges.
- `created_at TIMESTAMPTZ NOT NULL DEFAULT now()` on every synced table. The
  mobile sync engine stamps it on every push, so a table missing it rejects
  every write — this caused a full sync outage on 2026-08-31.
- IDs are `UUID` (`gen_random_uuid()`).

## Nullability matters as much as columns

The local SQLite mirror in `src/lib/db/schema.ts` must never be *stricter* than
Postgres. A column declared `NOT NULL` in the mirror but nullable here makes any
row carrying a null unstorable, which aborts the whole pull. `check-drift.sh`
guards this; it is not something the server can tell you.
